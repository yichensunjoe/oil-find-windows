Oil Find for Windows · 预览版 v0.1（Rust 实现）

适用范围
Windows 10/11 64 位电脑上的本机文件搜索。
不含 Pro 功能；不连接云端、不上传索引、无在线更新、无账号或激活。
搜索范围限本机文件。正文索引需要单独开启。

首次使用
1. 把 OilFind.exe 放到普通用户可写的文件夹；交付物就是这一个文件，无需解压其他内容。
2. 双击 OilFind.exe，无需安装任何运行时或管理员权限。
3. 首次打开索引设置会预选本机固定盘。核对范围和刷新间隔后点击“开始索引”。
4. 完成后在搜索框输入文件名、中文或拼音。双击结果打开；也可定位文件夹或复制路径。
5. 新文件/重命名/删除通过索引同步反映；首版采用定期目录快照而不是 NTFS USN 日志即时索引。可暂停，退出后停止。

界面操作
- 点击表头按文件名、完整路径、大小或修改日期对全部命中排序，最多显示排序后的前 2000 条。
  再次点击可反向排序，表头 ▲▼ 指示方向。默认按相关度排列。
- 右键结果行可打开、定位或复制路径。Ctrl+C 复制结果路径，Ctrl+L 聚焦搜索框。
- 扫描或启动加载缓存时，窗口底部细条显示不确定进度动画；标题栏与状态栏显示索引条目数（千分位）。
- 没有任何结果时，结果区显示引导文案（无索引 / 无匹配两种提示）。
- Ctrl+Alt+Space 唤出或最小化搜索窗。输入后展开结果，回车打开当前结果，Esc 最小化。
- 在“索引设置”里选择刷新间隔。首次索引成功后，应用运行期间会按间隔刷新。如需暂停，在设置中点击“暂停刷新”。

正文搜索
1. 打开“索引设置 → 正文索引”，添加单独授权的目录，再点击“开始正文索引”。
2. 回到搜索窗，点击“搜正文”，输入连续的原文词组，例如“海水淡化”。英文区分大小写。
3. 每份文件显示一行、命中片段、次数和首处位置。点击或按回车查看原文，用“上一处”“下一处”切换。
4. PDF 显示命中页面提取出的文字，Word 定位到正文段落，纯文本定位到行。“打开原文件”用系统关联程序打开。
- 支持含文本层的 PDF、.docx、.txt 和 Markdown。纯文本支持 UTF-8、带 BOM 的 UTF-16 和 GB18030。纯图片扫描件需有 OCR 文字层，受密码保护或无法解析的文档会跳过。
- 已开启文件名索引定时刷新的情况下，正文会随之刷新。也可在正文索引设置手动刷新。
- 单文件输入上限 32 MiB，提取文字上限 2 MiB，正文索引总量上限 20,000 份文件或 64 MiB 文字。超限文件会计入跳过数。
- “停用正文索引”取消正文授权并清理对应缓存。修改正文索引范围后需要重新点击开始。

搜索示例
报告              文件名/路径包含中文
baogao / bg       中文文件名全拼 / 首字母（不含声调，多音字首读音可能不准）
report budget     同时匹配
report | budget   任一匹配
report !draft     排除 draft（可匹配路径）
"年度 报告"       带空格的词组
*.pdf             整个文件名的通配符（支持 * 和 ?；[ ] 按普通字符处理）
ext:pdf;docx       扩展名筛选
kind:image        图片；也有 doc（含 WPS/OFD）/code/folder/video/audio/archive/app
file:report       仅文件；folder:项目 仅文件夹
size:>10mb        大小；size:1mb..5mb 为范围
size:>=1kb        支持 >、>=、<、<=、=
dm:today          今天；dm:week 为最近7个日历日
dm:2026-10-01     指定日期；dm:2026-10-01..2026-10-24 为闭日期范围
path:设计         路径包含
regex:^IMG_\d+    不区分大小写的正则；用带空格的 | 组合正则与其他 OR 条件

安全与索引
- 文件名索引读取文件名、路径、大小和修改时间。正文索引仅从单独确认的目录读取支持的格式，提取文字缓存保留在本机。
- 不提供删除、移动或重命名源文件的入口；配置和缓存会写入本机。
- 跳过：依赖与版本库目录（node_modules/.git 等）、私人运行器目录（.claude/.codex/.workbuddy 等）在任意层级；
  C:\Windows、C:\Program Files、C:\ProgramData、$RECYCLE.BIN 等系统目录仅在磁盘根目录一级跳过，
  因此 D:\code\myproject\windows 或 D:\work\tmp 这类普通项目目录仍可搜索。
- 跳过符号链接与目录联接；不支持 UNC/网络映射盘。OneDrive 占位文件如果带 reparse 属性会被跳过。
- 无法读取的子目录会跳过并计数。选中的索引根目录无法读取时，重扫失败并保留上一次成功的索引。
- 缓存和配置默认在 %LOCALAPPDATA%\OilFind；CLI 的 -cache 可指定其他本机文件，但不接受网络路径或链接，且会替换目标已有普通文件，不要指定个人文档。
- 搜索结果最多显示 2000 条，但同时展示总命中；索引上限 200 万条，超限会报错，不覆盖已有完整索引。
- 不保证达到上游 Mac SIMD/Everything 的性能，建议先索引工作目录，不要一开始选择整盘。
- 文件由你明确操作后交给 Windows 关联程序打开；请勿打开不可信文件。

安装与签名
预览版可执行文件未代码签名，Windows SmartScreen 或安全软件可能提示未知发布者。
下载渠道与是否签名由分发者决定；不要为此关闭系统防护或绕过安全策略。
单文件交付不写注册表、不装服务、不创建开始菜单项；退出后删除 exe 即可移除程序，
%LOCALAPPDATA%\OilFind 下的配置与索引需自行清理。

交付物
OilFind.exe   单文件：原生桌面客户端，C 运行库静态链接，不依赖 VC++ 运行库或同目录 DLL/数据文件。
             上游 MIT 许可与第三方 crate 声明已编入 exe；构建脚本只输出这一个文件。
许可文本：运行 `OilFind.exe --license` 弹出只读说明，内含 MIT 许可与第三方声明。
未随包分发：oilfind-cli 诊断工具（需从源码构建：cargo build --release -p oilfind-cli）。

源码位置
Windows 实现在 rust/（cargo workspace：oilfind-core / oilfind-win / oilfind-cli）；macOS 源码保留在 Sources/。
Windows 版重新实现了本地遍历/搜索与 Win32 界面，沿用上游公开功能和语法设计，不是把 Swift/AppKit 直接编译成 Windows。
开发者构建需要 Rust 1.92（rust/rust-toolchain.toml 已固定），运行端不需要。
