# 需求

## 目标

用户要求将 `https://github.com/oil-oil/oil-find` 完整克隆为独立新项目，以公开源码为基础修改后用于企业内部内网；明确不要未开源 Pro 模块。

后续确认：公司终端以 **Windows** 为主，第一阶段只做 **员工本机文件搜索**。因此新增独立 Windows 客户端，保留 macOS 上游源码。

## 范围

- 保存上游源码、完整 Git 历史和 MIT 许可证，建立 P088 独立项目。
- 移除私有模块的条件 target 与入口组装；固定公开模块构建。
- 编译期关闭上游在线更新，避免向公司网络发起版本检查或引入含 Pro 的官方包。
- 调整打包脚本为本分支离线包，包含 MIT 许可证，不接触上游发布站点。
- 构建、隔离测试、项目治理文件和可接力记录。
- Windows 客户端（`windows/`）：显式目录范围 + 后台元数据索引、文件名/路径/中文/拼音搜索、语法筛选、打开/定位/复制、离线缓存、原生 Win32 界面、离线打包与 PE 校验。

## 非目标

- 不获取私有代码、不破解授权、不下载含 Pro 的官方安装包。
- 不实现 Pro 替代功能，不部署官网/支付/授权服务。
- 不安装/启动应用、不扫描真实文件或 AI 会话，不接入企业内部网络，不创建远端或推送。
- 第一阶段不做 SMB/NAS 共享盘检索、多人服务、文件正文检索、删除/移动文件、在线更新与遥测。

## 约束

- macOS 仅 Apple 芯片 macOS 14+；Windows 仅 Windows 10/11 x64。
- 保留 MIT 版权和许可声明；分发副本时携带许可证与第三方声明。
- 在线更新硬关闭，不仅依赖用户偏好开关。
- Windows 默认不扫描任何目录，由员工显式选择范围；只读元数据；拒绝网络路径与重解析点。
- 沿用上游索引布局和确定性搜索（macOS），Windows 采用独立实现但保持公开搜索语法一致。

## 验收标准

- [x] 完整公开源码与历史已克隆。
- [x] Pro 不在源码树或编译 target 中，入口无私有导入。
- [x] 上游在线更新入口编译期禁用，设置解释禁用原因。
- [x] 本分支打包脚本不要求私有仓库、不发布至官网。
- [x] macOS 正式编译和隔离测试完成，结果记录到 HANDOFF。
- [x] Windows 索引/搜索/缓存测试通过，Windows GUI 与 CLI 可跨编译。
- [ ] Windows 真机验收：目录选择、列表交互、DPI、ACL、取消/重启、SmartScreen。
- [ ] 公司签名与离线分发策略确认。

## 假设与待确认项

- 默认独立成库；迁移到其他工作区属于单独决策。
- Windows 首版按“每台电脑各自索引本机目录”设计；共享盘检索不在本阶段。
- 部署前确认应用独立名称、Bundle ID/AppId、数据路径、AI 会话功能（Windows 首版未实现）、安全策略与管理员分发方式。
